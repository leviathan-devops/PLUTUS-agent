## PROBLEM

The charts tool (Tool 4) imports `TvChartController` from `engine3/tv-chart-controller.ts`. This component:
1. Connects to Chrome CDP on port 9228 (Chrome is on 6930)
2. Navigates TradingView internally
3. Captures screenshots internally
4. Runs VLM analysis via `TvChartImageFetch`

This is WRONG. Browser interaction is the AGENT'S job via MCP tools. Pipeline tools do DATA PROCESSING ONLY.

The Bible states in 3 places: TvChartController is LEGACY, BROKEN, REPLACED by TV Browser MCP v3.0.

## SOLUTION

### Part 1: Rewrite Tool 4 (charts) — VLM Analysis Only

**DELETE from charts tool:**
- `import { TvChartController, tvSymbolForPair }` (line 538)
- `const controller = new TvChartController()` (line 546)
- `await controller.connect()` and the FATAL return (lines 548-556)
- The entire browser navigation/screenshot loop (lines 558-596)
- `await controller.disconnect()` (line 598)
- `import { TvChartImageFetch }` (line 610)
- `const chartVision = new TvChartImageFetch(sdkClient)` (line 611)
- `chartVision.captureAndAnalyze(pair, VLM_PROMPT)` (line 631)

**ADD to charts tool:**
- New input parameter: `screenshots: Array<{ pair: string, timeframe: string, path: string }>`
- File existence verification for each screenshot
- Direct SDK client VLM analysis: readFile → base64 → sdkClient.prompt → parse zones
- NO fallbacks — empty screenshots = FAIL

**KEPT unchanged:**
- VLM prompt text (zone identification format)
- VLM response parsing (pipe-delimited ZONE|type|top|bottom|...)
- VLM zone → Engine 1 IP zone mapping
- ctx.validatedZones storage

### Part 2: Rename Manual Steps (D→E, etc.)

Since a new manual step (screenshot capture) is inserted between C and the old D:

| OLD | NEW | Description |
|-----|-----|-------------|
| Manual Step A | Manual Step A | Options screenshot (unchanged) |
| Manual Step B | Manual Step B | Zone map review (unchanged) |
| Manual Step C | Manual Step C | Shape chain review (unchanged) |
| — (new) | **Manual Step D** | **Agent captures TradingView screenshots via MCP** |

All references to "Manual Step D" in the codebase are renamed to "Manual Step E".
The new "Manual Step D" is the screenshot capture workflow.

### Part 3: Tool Execute After Hook — Manual Step Prompt Injection

After Tool 3 (shapes) completes, a `tool.execute.after` hook injects a mechanical prompt into the agent's context. This prompt contains:

1. **Exact MCP tool call sequence** for screenshotting each pair
2. **Anti-pattern warnings** (what NOT to do)
3. **Self-verification checklist** (agent must verify before proceeding)
4. **Success criteria** (what the agent must have before calling Tool 4)
5. **Tool 4 input specification** (exact args the agent must pass)

This prompt is NOT a suggestion — it is a MECHANICAL WORKFLOW that drives the agent forward. Same pattern as the v5.3.3 canon prompt's linear execution infrastructure.
