## 3. DOCTRINE FOUNDATION

### 3.1 The Anchor Doctrine (from PLUTUS_ANCHOR_DOCTRINE.md — canon)

Every trade setup is a 3-anchor chain:

```
[SL ANCHOR] — behind → [ENTRY ANCHOR] — overlapping → [LQZ sweep] — toward → [TP ANCHOR]
```

- **ENTRY ANCHOR:** a liquidity rung (LQZ) at the edge of a refined LTF zone nested inside an HTF S/D shell. Entry sits ON the rung. UNCHANGED from the fork — the proven A- precision mechanism (zone edge + forward spread: EUR 1, AUD 1.5, GBP 2, DXY 0.02).
- **SL ANCHOR:** the NEXT LQZ rung beyond the entry zone — one rung out, 2-5 pips in from its near edge (Law 7 pair buffers: EUR 2, GBP 3, AUD 3, DXY 5). Usually < 20 pips (golden DXY: 4-9.5p). Law-10 floor: never tighter than 0.5×ATR(1H). Law-8 fallback: entry ∓ max(zoneWidth×2, 1.5×ATR) when no rung within 100 pips. D17 ceiling: 36 pips HARD. T6 exception: entry directly against an unmitigated 4H BoM → SL at the block's near edge.
- **TP ANCHOR:** the nearest opposing zone of BoM/LQZ-overlap significance at TF ≥ entry TF, via Law-14 path walk. Significance: UM BoM (+100) > Earth+Fire liquidityScore ≥ 5 (+50) > BoM (+25) > MoM ≤1× (+15); depleted (3x+) excluded. Earth+Fire: midpoint if liquidityScore ≥ 5, near edge otherwise. Law-14 walk: pass through mitigated zones freely, cap at the first UNMITIGATED zone (with SIMULATED mitigation from prior setups in the same report). Law 12: TP TF ≥ entry TF. Law 13: >2×weeklyATR ambitious, >3× next candidate. TP min distance: ≥ 1.2× SL.

**Live-market mechanic:** you enter where someone else's stops just got taken (the sweep), you hide your stop behind the next liquidity shelf (where the next cluster of orders defends), and you exit where the next pool of stops sits (the opposing liquidity). The whole system is liquidity-to-liquidity.

### 3.4 The Dedup Doctrine (D39 — NOW UNDER INVESTIGATION for SP-1)

Dedup key = `direction_entry_sl_tp_day_category`. Same zone, different day → distinct. Same zone, same day, different category → distinct. Identical day+category+geometry → duplicate (killed).

**Consumption rule:** after a zone emits a setup as category C, re-firing C with identical geometry on a later day requires a genuine state change (simulated mitigation → freshness tier changed). Identical category + identical geometry + unchanged state = skip.

**⚠️ THE SUSPECT (SP-1):** the consumption rule allows re-fires when "state changed" — but EVERY setup simulates mitigation (reactionCount increments via the priorSetups ledger), so the state ALWAYS changes → the rule NEVER blocks multi-day re-fires in practice. Same zone re-fires every day with identical geometry = the 40-DXY inflation vector. The rule needs teeth: "state changed" must mean a genuine CONTEXT change (chain link, shape transition, category shift), not merely the trivial mitigation increment that every setup causes.

### 3.5 The No-Caps Doctrine (D38)

No MAX_SETUPS, no MAX_SETUPS_PER_DAY, no category caps. Volume = quality gates + retry loop + honest provenance + the semantic firewall. **NOTE:** this doctrine is NOT the problem — the problem is the consumption rule's toothlessness letting duplicate-geometry trades pass as "distinct" via day labels and trivial state changes. The fix is NOT caps — it's making the dedup/consumption machinery actually distinguish genuine multi-day trades from duplicate re-fires.

### 3.6 The Category Eligibility Model (D40)

Shapes are 1-2/day from the week-long chain. **DXY is the director, not the trader.** DXY setups define WHEN and in which DOLLAR direction the market moves. **The mechanical requirement the engine does NOT currently meet:** the translation is supposed to EMERGE from each pair's independent pipeline (same macro forces → inverse zones → inverse setups).
